[BLOCKER] #0b [FIXED] pyproject.toml had no wheel file-selection config, so any

  move the code into a `shellmentor/` package with a [project.scripts] entry
  point. That is a restructuring change, deliberately not bundled into a
  bug-fix release.

2. PROGRESSION AND DATA INTEGRITY
------------------------------------------------------------------------

[HIGH] #5  [FIXED] Three achievement triggers were hardcoded `lambda s, e: True`
           and fired on the first XP award.
  Verified before: award_xp(10) produced xp=1010, level=2 and unlocked
  speed_demon, pipeline_architect, portfolio_published.
  Verified after:  award_xp(10) produces xp=10, level=1, no achievements.
  FIX: real conditions — fastest recorded solve < 120 s, longest recorded
  pipeline >= 5 stages, and a persisted portfolio_generated flag.

[HIGH] #6  [FIXED] award_achievement() returned `conn.total_changes > 0`, which
           is cumulative for the connection.
  Verified after: first award True, duplicate award False.
  FIX: use cursor.rowcount.

[HIGH] #7  [FIXED] missions_completed counted every stage plus the completion
           (a 4-stage mission scored 5).
  FIX: new mission_history.is_final column (with migration; legacy stage-999
  sentinel rows are converted). record_mission_stage() no longer touches the
  counter; record_mission_complete() owns it, and get_completed_missions()
  reads is_final so a mission is no longer "complete" after stage 1.
  TEST: asserts missions_completed == 1 after a full mission.

[HIGH] #8  [FIXED] Mission stages accepted any non-empty string.
  FIX: stages are validated against their own `solution` with the same
  structural check challenges use. All 46 stages in missions.json carry one.
  TEST: junk input does not advance the mission.

[HIGH] #9  [FIXED] Lesson score was always 100% — `"CORRECT" in rendered_text`
           also matches "INCORRECT", so certificates were issued for all-wrong
           answers.
  FIX: correctness is tracked in `self._exercise_correct`, not scraped from
  rendered markup.

[HIGH] #10 [FIXED] The first-attempt XP bonus could never apply (attempts were
           incremented after the XP calculation).
  FIX: increment first, then calculate.

[HIGH] #11 [FIXED] The solved command was never stored — command_history was
           read but never appended to, so challenge_history.last_command was ''.
  FIX: submit_challenge() records the submitted command.
  TEST: asserts last_command equals the submitted solution.

[HIGH] #12 [FIXED] Failed challenge attempts were never persisted, so attempt
           counts, the analytics cards and suggest_difficulty() only saw wins.
  FIX: submit_challenge() calls progress_engine.attempt_challenge() on failure.

[HIGH] #13 [FIXED] Repeat completions inflated counters past the curriculum
           size.
  Verified after: three completions of the same lesson / three re-solves of the
  same challenge each leave the counter at 1.
  FIX: count only first completions; plus a one-off repair (see MIGRATION).

[HIGH] #14 [FIXED] Achievement XP was added with db.add_xp(), bypassing
           award_xp(), so achievement-driven level-ups fired no event or modal.
  FIX: single XP path — ProgressEngine._apply_xp() fires XP and level-up events
  and is used for both direct awards and achievement bonuses. DataManager no
  longer awards XP at all.

[HIGH] #15 [FIXED] Unreachable achievements.
  FIX: `commands_executed`, `quizzes_taken` and `quiz_correct` added to the
  stats dict; all 14 tracks mapped to trigger names (was 6); `all_tracks`
  retriggered on a real "14 tracks completed" condition instead of
  "lessons_completed >= 14"; perfect_score now means 5+ quizzes, all correct.
  Verified after: commands_1000 and pipeline_5_commands both evaluate True once
  their conditions actually hold.

[HIGH] #16 [FIXED] _try_award() granted achievements while ignoring their
           declared triggers (note_taker fired on the FIRST note).
  FIX: helper deleted; ProgressEngine.check_achievements() evaluates triggers.

[HIGH] #17 [FIXED] save_lesson_position() UPDATEd a row that only exists after
           completion, so resume never worked for a lesson in progress.
  FIX: upsert (insert a placeholder row when none exists).
  Verified after: position 3 saved and read back for a never-completed lesson.

[MED]  #18 [FIXED] Quiz XP was a flat 10 regardless of the "+N XP" shown.
  FIX: record_quiz_answer(correct, xp=...) takes the question's own reward;
  used_hint halves it.

[MED]  #19 [FIXED] Lesson exercise XP was advertised but never awarded (a bare
           `pass` with a comment).
  FIX: ProgressEngine.complete_exercise() awards it once per exercise per
  lesson; the UI shows "already credited" on a repeat.

[MED]  #20 [FIXED] Challenge/mission submissions recorded the command twice,
           inflating "Commands run".
  FIX: the extra submit_command() calls removed; the engines record once.

[MED]  #21 [FIXED] reset_all_progress() left challenge_streak and
           challenges_nohint intact.
  FIX: both cleared, plus last_active and the portfolio flag. Personal notes
  are deliberately preserved (a progress reset should not delete a user's
  notebook).
  NOTE: legacy github_token / github_user columns remain in old databases.
  They are unused, unread and harmless; dropping them would require a table
  rebuild, so they are left in place.

MIGRATION
  On first launch 4.4.0 runs DataManager.recompute_progress_counters() once
  (guarded by a schema_version row in a new `meta` table) and rebuilds
  lessons_completed, challenges_solved, challenges_nohint, missions_completed
  and commands_executed from the history tables, correcting values inflated by
  #7 and #13.

[MED]  #28 [FIXED] The resume prompt had no effect — start_lesson() had already

[LOW]  #29 [FIXED] The dashboard re-parsed its whole ASCII block every second.
  FIX: cosmetic animation moved to 3 s, data refresh to 15 s.

[LOW]  #30 [FIXED] ChallengeScreen never stopped its countdown when popped, and
           the input stayed live after a timeout.
  FIX: on_unmount() stops the timer; timeout disables input and Submit; Retry
  re-enables them.

[LOW]  #31 [FIXED] Note export built a filename from raw user input, so a title
           containing "/" or ".." escaped ~/ShellMentor_Exports.
  FIX: the name is sanitised to [A-Za-z0-9._-] and length-capped.

[LOW]  #32 [FIXED] Escape discarded unsaved note edits silently.
  FIX: NotesScreen compares the editor against the stored note and asks for

5. WHAT WAS ALREADY SOLID  (unchanged)
------------------------------------------------------------------------
- The no-execution policy is genuinely honoured: no subprocess/os.system/eval
  anywhere in the tree; PlaygroundEngine.submit_command only records, and the
  achievement trigger evaluator is a hand-written parser rather than eval().

  10 missions, 31 achievements, 12 ranks — every record has the keys the code
  reads, no duplicate ids, and rank thresholds in achievements.json match
  data_manager._compute_level() exactly.
- Schema migrations for added columns are handled defensively, and the module
  split (ui_core / ui_screens / ui_activities) is a clean separation.
