ShellMentor v4.5.0 — What Has Been Done
==========================================
Professional Linux Command-Line Learning Platform
Reviewed: September 2026 | 14 Python files | ~8,000 lines

MODULE BREAKDOWN
----------------

main.py (750 lines)
  App entry point. Theme registry from YAML (now feeding real Textual CSS
  variables, not just a handful of widgets), OS username detection,
  session time tracking (30s flush), keyboard bindings (Ctrl+L/G/H/M/A/N/R/T/D/U/P/Q),
  command palette with search. Clean lifecycle: DB close + time flush on quit.
  Engine init order: DataManager -> LearningEngine -> ProgressEngine ->
  ChallengeEngine (with progress_engine) -> PlaygroundEngine.

ui_core.py (478 lines)
  Shared foundation. BaseScreen template (sidebar + header + footer + render_content()).
  NavButton, NavigationSidebar widgets. Five modals: LevelUp, Achievement,
  Hint, Confirm (redesigned: header, wrapping, auto-height, right-aligned
  buttons), Certificate (now with a "Save to File" button).

ui_screens.py (1,977 lines)
  8 screens. DashboardScreen: ASCII logo, animated progress bar, streak indicators,
  a top action bar with a quick Reset Progress button. LessonsScreen: track/lesson
  browser with difficulty indicators and bookmark stars, section viewer, exercises,
  quizzes, estimated time remaining, resume prompt. PlaygroundScreen: terminal, file
  browser, pipeline templates. NotesScreen: search/edit/save with proper export
  directory. AnalyticsScreen: bar charts, weekly activity, challenge performance,
  level progress. SettingsScreen: theme selector (live preview), default Timed Mode
  duration, backup export/import, portfolio export, About section, keyboard
  shortcuts. EnvScanScreen: first-run system detection.

ui_activities.py (910 lines)
  ChallengesScreen: difficulty filter with auto-suggestion, a Timed Mode switch +
  duration picker before starting. ChallengeScreen solver with countdown timer,
  retry button, a "why this works" pipeline breakdown after solving (and on
  abandon/timeout), confirmation dialog before abandon. MissionsScreen: async
  stage progress, MissionScreen runner. AchievementsScreen: rarity grouped with
  async rendering.

learning.py (476 lines)
  Track/lesson engine with difficulty-aware track stats (avg difficulty + icons).
  QuizSession with scoring. Exercise validation: output regex + shlex token overlap.
  Bookmark toggle, resume from saved position, estimated time remaining.
  Command translator: 7 task categories. Regex visualizer. Full-text search.

challenge.py (394 lines)
  Challenge validation. `start_challenge(id, time_limit_override=...)` lets the UI's
  opt-in Timed Mode force a countdown independent of the challenge's own data. XP
  formula: base * hint_factor * speed_factor * attempt_factor * streak_factor
  (+5% per streak, capped at +50%). Streak tracking (increment on solve, reset on
  abandon). Difficulty suggestion (80%/30% threshold). Mission mode with stage
  progression.

playground.py (641 lines)
  Command recording wrapper (never executes). Autocomplete: 50+ templates. 8
  pipeline templates. `explain_pipeline()` splits a command on unquoted `|` and
  describes each stage from an expanded ~28-command help table — the basis for
  challenges' "why this works" breakdown. Session recording/export. Diff viewer.

progress.py (321 lines)
  Gamification coordinator. XP events with callbacks. Achievement evaluation:
  compound AND/OR triggers without eval(). 12-level ranking. Portfolio generation.

data_manager.py (1,114 lines)
  SQLite with WAL journaling. 13 tables. Level computation (12 thresholds).
  Streak tracking (daily + challenge streak). Achievement trigger evaluator.
  Note search. Enhanced analytics summary with weekly activity, challenge
  performance, average/best solve times. Lesson position save/resume.
  Bookmark toggle. Certificate issuance. `export_backup()`/`import_backup()`
  round-trip every progress table to/from one JSON file, with column names
  checked against the live schema before use. Reset progress preserves theme.

utils.py (484 lines)
  SystemInfo detection. Package manager detection. Text utilities —
  `safe_export_filename()` (shared by notes, certificates and backups) and
  `split_pipeline()` (quote-aware `|` splitting, used by explain_pipeline()).
  No execution helpers of any kind: nothing in this codebase ever calls
  subprocess, os.system, eval or exec on a learner's input.

test_core.py (171 lines)
  13 tests: non-execution guarantee, command recording, output validation,
  challenge answer structure, level computation, XP formatting,
  safe_export_filename, split_pipeline, explain_pipeline, Timed Mode
  override, backup export/import round trip, bad-backup rejection.

test_ui_smoke.py (221 lines)
  7 headless-pilot tests: every screen mounts, analytics renders for a new
  user, a challenge screen scores a solution, Timed Mode forces a
  countdown, a mission counts one completion and rejects junk, achievement
  rows render, the Dashboard's own Reset Progress button works.

    modals — Textual validates a class's DEFAULT_CSS on first use, and
    this could crash the whole app before the dashboard ever appeared
24. Fixed silent failure: color: grey50 (valid in Rich markup, not in
    Textual CSS) in Achievement/Certificate modals meant those popups
    never rendered — swallowed by the achievement callback's exception
    handler, with no visible error
25. Fixed invisible button/nav-item text under Professional Light: primary
    buttons used $primary-background as their fill with $primary as the
    text color, and those two are identical under that theme
26. Added 8 new unit/UI tests covering all of the above
